NOTIFICATION FLOW ANALYSIS:
├── Frontend Polling
│   └── NotificationsProvider calls /check-plan-expiry every 5 minutes
├── Page Reloads
│   └── Each page load could trigger endpoint again
├── Server-Side Cron
│   └── Potential backend job calling endpoint
└── Result: Multiple calls creating duplicate notifications ❌

ROOT CAUSE: NO IDEMPOTENCY
  • checkAndCreatePlanNotifications() creates notifications unconditionally
  • No tracking of which notifications were already created
  • Multiple identical notifications created for same plan/trigger
  • Example: User sees "Plan expires in 1 hour" notification 3-5 times

╔════════════════════════════════════════════════════════════════════════════╗
║  SOLUTION ARCHITECTURE                                                     ║
╚════════════════════════════════════════════════════════════════════════════╝

NEW TRACKING TABLE
┌─────────────────────────────────────────────────┐
│ plan_notification_tracking                      │
├─────────────────────────────────────────────────┤
│ id (UUID) [PK]                                  │
│ plan_id (FK → user_plans)                       │
│ user_id (Reference)                             │
│ trigger (7_days|24_hours|1_hour|expired)        │
│ created_at (Timestamp)                          │
│ expiry_date_snapshot (Timestamp)                │
├─────────────────────────────────────────────────┤
│ Indexes:                                        │
│  • (plan_id, trigger) COMPOSITE [FAST LOOKUP]   │
│  • user_id [FOR RETENTION]                      │
│  • created_at [FOR CLEANUP]                     │
└─────────────────────────────────────────────────┘

FLOW WITH IDEMPOTENCY
┌─────────────────────────────────────────────────┐
│ checkAndCreatePlanNotifications()                │
├─────────────────────────────────────────────────┤
│ 1. Get all plans needing notifications           │
│ 2. FOR EACH plan:                               │
│    a. Check if notification already exists      │
│       SELECT * FROM tracking                    │
│       WHERE plan_id = X AND trigger = Y         │
│    b. IF EXISTS: Skip (no duplicate)            │
│    c. IF NOT: Create + Record                   │
│ 3. Return stats (created, checked, skipped)     │
│ 4. Response shows idempotency working           │
└─────────────────────────────────────────────────┘
